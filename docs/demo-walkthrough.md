# Five-minute, interview-friendly demonstration

**00:00 — Explain the objective.** SignalForge 720 is a local learning system that links public threats to a defensible case workflow. It does not scan networks or confirm exploitation.

**00:40 — Load the signature lab.** Click **Load 720 signature lab**: four explicitly fictional cases and three fictitious assets. Open the Signal Board and show transparent priority explanations.

**01:30 — Triage a case.** Open the Analyst Queue and record a note for the synthetic fictional VPN incident. Explain why source metadata, EPSS, and validated exposure are different.

**02:15 — Examine the Exposure Lab.** Point out exact CVE-to-asset intersections with *invented* CVE-2099-* identifiers. Explain that declared CVE inventory is not a verified vulnerability assessment.

**03:10 — Detection Lab.** Show an ATT&CK-inspired hypothesis and the required telemetry. Export a safe validation worksheet rather than claiming you built a production Sigma detection.

**04:10 — Evidence Binder.** Select the same case; download Markdown/JSON, explain evidence prompts and compare SHA-256 canonical data digests. A checksum is not an authenticated signature or auditor sign-off.

**04:45 — Close.** Open Content Studio and export a distinctive source-linked post card. State that external posts require human review. Finish with the technical limitations and next steps: Wazuh telemetry integration, affected-version mapping, and tested analytics.
